## 3. トップ `/` の構成

順序は仕様 §2 のとおり「訪問者の疑問に答える順」。

### 3.1 ヒーロー（#hero）

- 答える疑問：ここは何のサイトか。
- 要素：キッカー／H1／リード（いずれも確定済み文言。仕様 §1）。
- 備考：とりあえず47 への導線は**ここには置かない**——主読者は just47 から来ており「戻る」導線の価値が低い。導線は 3.2 の自社アプリ項とフッターが担う。CTA ボタンも置かない（受注サイトにしない）。

### 3.2 事業内容（#services）

- 答える疑問：何をしている集まりか。
- 要素：3項目（各＝見出し＋2〜3文の記述体）。
  1. **クラウド導入支援・インフラ構築** — AWS / Google Cloud / Azure。設計・構築・運用、技術支援・教育まで。
  2. **AI の開発・業務導入支援** — 生成AI（RAG）基盤の構築、AI を組み込んだ開発、活用の教育・伴走。
  3. **自社アプリの企画・開発・運営** — 「とりあえず47」（リンク：`NEXT_PUBLIC_PORTAL_URL`）。「本業と同じ技術・品質基準で」の一文をここで回収する。
- 備考：料金・導入フロー・問い合わせ誘導は書かない（仕様 §1）。

### 3.3 実績（#works）

- 答える疑問：本当に技術力があるのか。
- 要素：業界名ベースのハイライト4〜5件（候補。文言はドラフトで確定）：
  - 大手自動車メーカー — 車両データ×生成AIのデータ活用基盤（Google Cloud）
  - クレジットカード会社 — 生成AI（RAG）環境の構築（AWS・Azure）
  - 大手飲料メーカー — 生成AI環境の構築（AWS）
  - 小売（ネットスーパー） — AWS 導入・サーバーレス化
  - 開発会社への技術支援 — AWS 設計支援・資格取得の教育
- 備考：社名・個別サービス名は出さない（仕様 §1 の語彙規約）。件数を盛らない。**資格は記載しない**（決定）。

### 3.4 沿革（#history）

- 要素：確定済みの4行の表（仕様 §1）。2026 行はアプリ公開後に「開始」→「公開」へ差し替え。

## 4. `/contact` の構成

1. ページ見出し＋リード：役割分担の案内「アプリの不具合・ご要望は とりあえず47 のお問い合わせへ」（リンク：`NEXT_PUBLIC_PORTAL_URL` + `/contact`）。
2. フォーム：姓・名／メール／件名／本文／（不可視のハニーポット）／送信ボタン。**カテゴリ選択は置かない**（アイビーラボ宛の連絡のみを受け付け、アプリ窓口は冒頭案内で誘導するため）。
3. 送信内容の取り扱いについて `/privacy` への参照リンク。
4. 状態表示：送信後サンクス（同一ページ内で置換）／送信エラー／レート制限の拒否文言／SW 未制御の案内（再読み込みで解決しうる）／SW 非対応の案内（フォーム非描画・最新ブラウザ案内）。

- 備考：挙動の正は仕様 §5。本書は画面要素の配置のみを定める。

## 5. `/privacy` の構成（見出し案）

1. 適用範囲 — 本ポリシーは www.aibee-lab.jp に適用（アプリ・とりあえず47 のポリシーは各サイト側に置く旨の一文で混同を防ぐ）
2. お問い合わせで取得する情報と利用目的（保存・返信・通知）
3. スパム対策のための IP のハッシュ化・一時保持（自動削除）
4. Cookie について — **使用しない**（明記）
5. ホスティング — AWS 上で保管
6. 本ポリシーの改定について
7. お問い合わせ先（`/contact`）
8. 制定日

- 備考：読みやすさ優先のテキストページ。法律家調にしない。
